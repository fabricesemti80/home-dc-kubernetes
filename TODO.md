# Infrastructure roadmap

Durable, reviewed work queue for `home-dc-kubernetes`, `home-dc-proxmox`, `home-dc-terraform`, and the parent `home-dc` documentation repository. This is a planning list, **not** authorization to apply Terraform, delete workloads/data, or change the physical infra-cluster. Work one bounded change at a time; branch/PR for risky changes. Record assumptions, validation, migration and rollback in the linked design plan **before** introducing infrastructure code. Reconcile these items with observed live state before marking them done.

## Next: recovery and observability

-   [ ] **Offsite config/database backups (both clusters).** Inventory all node-local `local-path` PVCs, Doppler/secret-bootstrap dependencies, Argo settings and NAS media/Immich originals; distinguish application-consistent DB dumps from filesystem snapshots. Select an encrypted offsite destination and scoped credentials, schedule GitOps-managed backups where supported, alert on failures, and **restore** at least one copy of every critical app class onto a disposable target. Do not assume a retained PV, NAS snapshot on the same appliance, or a secret manager protects local PVCs. Rollback: retain existing storage/backups and disable only the new backup jobs.
-   [ ] **Assess Pulse replacement and optional Uptime Kuma replacement with VictoriaMetrics.** VictoriaMetrics stores metrics; it is not itself a Pulse UI, synthetic uptime checker or alert delivery service. Inventory Pulse/agent, Uptime Kuma/AutoKuma monitors and notifications first; design the necessary scraping, probing, alerting and dashboards alongside metrics storage, then prove equivalent host/Proxmox/Kubernetes visibility and external route alerts **before** retiring either existing service. Explicitly decide whether Uptime Kuma remains; preserve monitoring history/backup and a fast revert.

## Ownership and platform

-   [ ] **Separate app-cluster and infra-cluster Argo CD control planes.** Today app-cluster Argo manages Applications targeting both clusters; design independent infra-cluster bootstrap, repository credentials, root apps, secrets and access policy. Migrate ownership once, compare rendered/live objects and finalizers, test infra GitOps sync without app-cluster availability, then remove cross-cluster credentials only after both roots reconcile. Do not touch physical Talos nodes as an incidental part of this work; maintain rollback to the current Argo hub until infra is self-hosting.
-   [ ] **Consolidate Terraform/OpenTofu code and state in `home-dc-terraform`.** Inventory roots in all related repositories, backend/state locations and resource ownership (including Cloudflare/local DNS and Proxmox). Move code with explicit module/back-end migrations and state backups; use import/moved/state operations only with a reviewed resource map and a no-destroy plan. Never apply an old and new root to the same resources, copy live credentials into Git, or destroy the old state before the new root is independently proven. Keep `home-dc-proxmox` host ownership distinct.
-   [ ] **Migrate from Doppler operator to 1Password.** Decide the actual 1Password integration and bootstrap method, scope read permissions per cluster and namespace, inventory every DopplerSecret and consumer, and move values without printing/committing them. Run old and new reconciliation side by side only with explicit conflict avoidance; validate secret rotation, pod rollout and recovery after operator outage. Remove Doppler CRs/tokens/operator only after every consumer and a rollback path are verified.

## Documentation and repeatability

-   [ ] **Clean up Kubernetes docs.** Separate current operating procedures from historical migrations, reconcile app catalog and live namespace inventories, remove stale Ceph/current-cluster claims and Terraform locations, and keep security/restore limitations visible. Preserve incident history rather than rewriting it as current architecture. Validate links and commands against the actual kubeconfigs and deployment.
-   [ ] **Make task lists lean across `home-dc-proxmox`, `home-dc-terraform`, and `home-dc-kubernetes`.** Audit task names and callers, retire commands for moved roots/old clusters, provide explicit environments and non-destructive defaults, then smoke-run list/help/plan or dry-run entry points in each repo. Keep documented bootstrap, restore and rollback actions reproducible; never test an apply or destroy as a harmless smoke check.
-   [ ] **Update cross-repository diagrams and documentation in `home-dc`.** Explain repository boundaries, standalone PVE `pve-00`, one-controller/three-worker app-cluster, unchanged two-node physical infra-cluster, NFS and node-local state, GitOps ownership, DNS/Cloudflare ingress and secrets/backup flows. Revise diagrams only after the related design decision is implemented; validate links and each depicted live dependency.
