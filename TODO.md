# Infrastructure roadmap

Durable, reviewed work queue for `home-dc-kubernetes`, `home-dc-proxmox`, `home-dc-terraform`, and the parent `home-dc` documentation repository. This is a planning list, **not** authorization to apply Terraform, delete workloads/data, or change the physical infra-cluster. Work one bounded change at a time; branch/PR for risky changes. Record assumptions, validation, migration and rollback in the linked design plan **before** introducing infrastructure code. Reconcile these items with observed live state before marking them done.

## Preferred sequence

Sequence follows recovery and ownership dependencies, not a promise to tackle every item immediately. Small independent follow-ups below may run between these changes. **Backups precede Argo separation:** independent controllers do not protect node-local databases and make recovery more complex. **1Password precedes the split:** prove secret bootstrap in both clusters before either Argo installation must stand alone.

Do not assume a retained PV, NAS snapshot on the same appliance, or a secret manager protects local PVCs. Rollback: retain existing storage/backups and disable only the new backup jobs.

2. [ ] **Provide an authenticated NFS media file manager with delete/restore.** After backups are proven, evaluate a maintainable UI for browsing, moving, and deleting movies, series and download folders on the existing NAS export without SSHing into the NAS. Design **least-privilege mounts** (media paths only, never Immich originals, app configs or NAS snapshots), a private/Tailscale-only route by default, app authentication, a trash/quarantine step and tested restore before permitting permanent deletion. Confirm UID/GID and NFS permissions from the actual container; do not grant blanket write access to all NFS content. Document how to remove/unmonitor a title in Sonarr/Radarr before deleting files so automatic searches do not fetch it again, and avoid deleting active torrent data while seeding. GitOps-manage deployment and a rollback that preserves files.
3. [x] **Consolidate OpenTofu infrastructure in `home-dc-terraform`.** Active Proxmox and Cloudflare configuration/state now live there; old Kubernetes-repository state snapshots are archived privately after apply. Local DNS is Technitium-managed, so no local-DNS OpenTofu root remains here. `home-dc-proxmox` retains host ownership.
4. [ ] **Migrate from Doppler operator to 1Password.** Decide the actual 1Password integration and bootstrap method, scope read permissions per cluster and namespace, inventory every DopplerSecret and consumer, and move values without printing/committing them. Run old and new reconciliation side by side only with explicit conflict avoidance; validate secret rotation, pod rollout and recovery after operator outage. Remove Doppler CRs/tokens/operator only after every consumer and a rollback path are verified.
5. [ ] **Separate app-cluster and infra-cluster Argo CD control planes.** Today app-cluster Argo manages Applications targeting both clusters; design independent infra-cluster bootstrap, repository credentials, root apps, secrets and access policy. Migrate ownership once, compare rendered/live objects and finalizers, test infra GitOps sync without app-cluster availability, then remove cross-cluster credentials only after both roots reconcile. Do not touch physical Talos nodes as an incidental part of this work; maintain rollback to the current Argo hub until infra is self-hosting.
6. [ ] **Assess Pulse replacement and optional Uptime Kuma replacement with VictoriaMetrics.** VictoriaMetrics stores metrics; it is not itself a Pulse UI, synthetic uptime checker or alert delivery service. Inventory Pulse/agent, Uptime Kuma/AutoKuma monitors and notifications first; design the necessary scraping, probing, alerting and dashboards alongside metrics storage, then prove equivalent host/Proxmox/Kubernetes visibility and external route alerts **before** retiring either existing service. Explicitly decide whether Uptime Kuma remains; preserve monitoring history/backup and a fast revert.
7. [ ] **Make task lists lean across `home-dc-proxmox`, `home-dc-terraform`, and `home-dc-kubernetes`.** Audit task names and callers after ownership/bootstrap moves, retire commands for moved roots/old clusters, provide explicit environments and non-destructive defaults, then smoke-run list/help/plan or dry-run entry points in each repo. Keep documented bootstrap, restore and rollback actions reproducible; never test an apply or destroy as a harmless smoke check.
8. [ ] **Clean up Kubernetes docs.** Separate current operating procedures from historical migrations, reconcile app catalog and live namespace inventories, remove stale Ceph/current-cluster claims and Terraform locations, and keep security/restore limitations visible. Preserve incident history rather than rewriting it as current architecture. Validate links and commands against the actual kubeconfigs and deployment.
9. [ ] **Update cross-repository diagrams and documentation in `home-dc`.** Explain repository boundaries, standalone PVE `pve-00`, one-controller/three-worker app-cluster, unchanged two-node physical infra-cluster, NFS and node-local state, GitOps ownership, DNS/Cloudflare ingress and secrets/backup flows. Revise diagrams only after the related design decision is implemented; validate links and each depicted live dependency.
