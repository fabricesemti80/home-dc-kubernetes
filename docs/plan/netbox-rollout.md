## 📌 Namespace

Use `netbox` — NetBox is infrastructure tooling (IPAM/DCIM), so it lives on
`infra-cluster` in its own namespace, matching how Kestra gets `kestra`.

## 💡 Kubernetes Shape

-   Argo CD app: `kubernetes/argo/apps/infra-cluster/netbox.yaml`
-   App config: `kubernetes/apps/infra-cluster/netbox/`
-   Helm chart: `netbox` 8.3.49 from `https://netbox-community.github.io/netbox-chart` (vendors bitnami postgresql + valkey subcharts, no OCI needed)
-   Components: web (1 replica), worker (1 replica), housekeeping cron (02:00 Europe/London), postgres (standalone), valkey (standalone)
-   Service port: 80 (ClusterIP)
-   Internal route: `netbox-internal` → `envoy-internal`, host `netbox.krapulax.home`
-   External route: `netbox-external` → `envoy-external`, host `netbox.krapulax.dev`, external-dns → `external-infra.krapulax.dev`

### Capacity & limits (reviewed against host capacity 2026-08)

Infra cluster is 2 nodes: `infra-cp-01` (5.95 CPU / 15.5Gi) and `infra-wk-01`
(3.95 CPU / 7.5Gi, memory limits already ~63% used). NetBox is pinned to
`infra-cp-01` (same node as Kestra, which is already there) and every component
has an explicit limit that fits the host:

| Component | Requests | Limits | Notes |
|---|---|---|---|
| netbox web | 500m / 1Gi | 750m / 1536Mi | `medium` preset, explicit |
| worker | 250m / 512Mi | 500m / 768Mi | chart default is **none** (no limits) — overridden |
| housekeeping | 100m / 128Mi | 150m / 192Mi | cron, nano |
| postgres | 250m / 256Mi | 380m / 384Mi | micro, standalone, 8Gi local-path |
| valkey | 100m / 128Mi | 150m / 192Mi | nano, standalone, cache only (no PVC) |

Total ≈ 1.2 CPU / 2Gi requests — fits the ~4.8 CPU / ~10Gi headroom on
infra-cp-01 without touching the busy worker node.

### Secrets

-   Doppler (`project: home-dc-kubernetes`, `config: infra`) → `netbox-config`
    (`secret_key`) and `netbox-superuser` (`username`, `password`, `email`,
    `api_token`), using the repo's DopplerSecret pattern.
-   Postgres and Valkey auth are auto-generated by the bundled subcharts.

## 🔐 Security Impact

-   NetBox holds the network inventory (IPs, devices, credentials metadata), so
    the **external route is gated by Cloudflare Access allow-only** (same as n8n
    and HomeTube). The internal route is LAN-only.
-   Pods are pinned to infra-cp-01 with control-plane toleration, matching the
    Kestra pattern.
-   `allowedHosts` restricted to the two NetBox hostnames.
-   The `netbox` namespace enforces `pod-security.kubernetes.io/enforce: restricted`.
