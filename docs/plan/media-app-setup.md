# App-cluster media setup on the NAS

Use this runbook after the GitOps media Applications are Healthy. It records the **observed** NAS layout and container mounts, then the **manual UI configuration still required**. The architecture is in [Media Management Stack](../architecture/MEDIA_MANAGEMENT_STACK.md); this is not a source of API keys or passwords.

## Storage and safety baseline (verified 2026-10-29)

-   The retained, RWX `media-library-pvc` is Bound to `media-library-pv`, NFSv4.1 `10.0.40.2:/media`, reclaim policy `Retain`. App-owned `/config`, Immich PostgreSQL/Redis and caches instead use node-local `local-path` PVCs. Doppler secrets do **not** back up those PVCs.
-   The NAS export contains `tv` (27 immediate directories), `movies` (51), `downloads/{complete,incomplete}`, and `immich/{library,upload,encode,thumbs,profile,backups,encoded-video}`. The legacy `_library/{Movies,TV_Shows}` is a **different** tree: do not silently use it as the Sonarr/Radarr root or move it. Leave NAS snapshots, old `tdarr-cache`, and other existing directories untouched.
-   Read/write/delete probes succeeded in SABnzbd's `/downloads` and `/incomplete-downloads`, Sonarr's `/media/tv`, Radarr's `/media/movies`, and Immich's `/data`. The current images run with `PUID=0`, `PGID=0`; observed write access is **not** a recommendation to expand NFS permissions. Check application authentication before using any public route.
-   The Immich pod has a read-only `/external-library` mount of `immich/library`. At least 3,508 image/video files were visible within four directory levels; that proves the source is present, **not** that the new Immich database has indexed them. `/data` is the same NFS `immich` tree, mounted separately for new uploads. Never scan `/data` as an external library or copy the external library into `/data`: that risks duplicate assets and modifies the legacy source.

Container paths, **not NAS paths**, go into each application's UI. SABnzbd and qBittorrent report `/downloads/...` to Sonarr/Radarr. The latter already see that path, so ordinary completed-download import needs no Remote Path Mapping. All connections between pods should use the Kubernetes service names below, not public Cloudflare hostnames or changing pod IPs. `Transmission` is **not deployed**; the configured torrent client is qBittorrent. Do not enter an invented Transmission hostname in Sonarr.

## Configure download clients first

### SABnzbd: Usenet

1. In **Settings → Folders**, set **Temporary Download Folder** to `/incomplete-downloads` and **Completed Download Folder** to `/downloads`. Replace any first-run `/config/Downloads/...` defaults. The folders are shared NAS mounts, not local config disk.
2. In **Settings → Servers**, add the Usenet provider's real hostname, port, TLS choice and credentials. These are provider-specific; do not paste them into Git or this runbook. In **Settings → General**, configure application login and retrieve the SABnzbd **API key** for Sonarr/Radarr.
3. In **Settings → Categories**, create `tv` and `movies`. If using the category **Folder/Path** field, use relative subfolders `tv` and `movies` beneath `/downloads`, not `/media/tv` or `/media/movies`: the \*arr app performs the final import. Keep category spelling identical in the download-client entries below.
4. In **Settings → Switches → Post processing**, enable unpacking/recursive unpacking and normally keep post-processing limited to verified jobs. A queue item that finishes as only `.rar`/`.par2` files, or fails repair, gives Sonarr/Radarr nothing importable; inspect SABnzbd History rather than changing library paths.

### qBittorrent: torrents (not Transmission)

1. In **Options → Downloads**, set **Default Save Path** `/downloads`; enable **Keep incomplete torrents in** and set `/incomplete-downloads`. Create categories `tv` and `movies` (their save paths should stay under `/downloads`, not in the final libraries). In **Options → Web UI**, keep authentication enabled; the WebUI password is provisioned from the `home-dc-kubernetes/apps` Doppler config, not stored in Git.
2. Sonarr/Radarr connect to host `qbittorrent.media.svc.cluster.local`, WebUI port `8080`, with the WebUI credentials; **URL Base** blank, **SSL** off for in-cluster HTTP. Peer traffic is separate: the `qbittorrent-peer` LoadBalancer is `10.0.40.104:6881` TCP/UDP. A WAN router forward is optional for torrent connectivity and is **not** a WebUI port forward; never publish port `8080` that way.

## Configure managers and indexing

1. In **Sonarr → Settings → Media Management** set the root folder to `/media/tv`; use **Series → Library Import** to discover the existing shows without relocating or deleting them. In **Radarr**, use `/media/movies` and **Movies → Library Import**. Enable **Completed Download Handling** under **Settings → Download Clients** in each app. New application databases do not automatically know about NAS files.
2. In **Sonarr → Settings → Download Clients → + → SABnzbd**, enter host `sabnzbd.media.svc.cluster.local`, port `8080`, SSL off, blank URL Base, the SABnzbd API key, and category `tv`. In **Radarr**, use the same host/port/key with category `movies`. **Test**, then save each client.
3. If using torrents, add **qBittorrent** under the same Download Clients menu: host `qbittorrent.media.svc.cluster.local`, port `8080`, WebUI username/password, category `tv` in Sonarr or `movies` in Radarr, SSL off, blank URL Base. **Test** before saving. If both clients are enabled, choose their priority in each app; Prowlarr is not a download client and does not replace either one.
4. In **Prowlarr → Indexers**, add and test only the Usenet/torrent indexers you actually use. In **Prowlarr → Settings → Apps → + → Sonarr**, set the **Prowlarr Server** URL to `http://prowlarr.media.svc.cluster.local:9696` and the **Sonarr Server** URL to `http://sonarr.media.svc.cluster.local:8989`; use Sonarr's API key from **Settings → General**, blank URL Base and **Full Sync**. Add **Radarr** likewise at `http://radarr.media.svc.cluster.local:7878` with its own API key. Test each application connection. Prowlarr pushes indexers to Sonarr/Radarr; you do **not** put the Prowlarr hostname in Sonarr's Download Clients list. Prowlarr's own download-client configuration is optional for searches performed inside Prowlarr.
5. **Recyclarr** has no UI: its GitOps config targets the above Sonarr/Radarr service URLs and runs on `CRON_SCHEDULE="0 4 * * *"` with `TZ=Europe/London`. Put the current `SONARR_API_KEY` and `RADARR_API_KEY` in the scoped **Doppler project `home-dc-kubernetes`, config `apps`**; `recyclarr-secrets` syncs them into namespace `media`. Check its logs after sync before choosing the generated `Series 1080p`/`Movies 1080p` profiles. Recyclarr changes quality profiles/custom formats, **not** clients, indexers, or root folders. Never print or commit API keys.

### Import performance: optional qBittorrent hardlinks

A real link probe from Sonarr's `/downloads` into `/media/tv` failed with `Cross-device link`, even though both paths are on the same NAS. Importing that way copies torrent files while the original is retained for seeding. For hardlinks instead, configure **Remote Path Mappings** separately in Sonarr and Radarr for **Host** `qbittorrent.media.svc.cluster.local`, **Remote Path** `/downloads/`, **Local Path** `/media/downloads/complete/`. The Host must match the qBittorrent download-client entry. The \*arr app then accesses source and library through its single `/media` mount; a link probe between `/media/downloads/complete` and `/media/tv` succeeded with two links. Test a legal small download and confirm both import and seeding before relying on this optimization. Do not apply this mapping to SABnzbd (its existing shared `/downloads` path already works), and do not enable an unverified hardlink-only policy.

## Configure viewers and photos

1. Complete Jellyfin's admin setup and in **Dashboard → Libraries → Add Media Library** add a **Shows** library at `/data/tv` and a **Movies** library at `/data/movies`. Jellyfin mounts the NAS root at `/data`, unlike Sonarr/Radarr's `/media`; `/downloads` is not a library. Scan and confirm existing series/movies are visible. The pod runs on `k8s-wrkr-01-gpu` with `nvidia.com/gpu: 1`; configure NVIDIA hardware acceleration under **Dashboard → Playback → Transcoding** only for supported codecs and confirm an actual transcode during playback. `Healthy` at `/health` alone is not a transcode test.
2. Complete **Jellyseerr** setup privately at `http://requests.krapulax.home`: connect Jellyfin at `http://jellyfin.media.svc.cluster.local:8096` with a Jellyfin administrator; then add Sonarr (`http://sonarr.media.svc.cluster.local:8989`) and Radarr (`http://radarr.media.svc.cluster.local:7878`) using their individual API keys. Select Sonarr root `/media/tv` and Radarr root `/media/movies` in Jellyseerr; those strings refer to the \*arr pods, not Jellyseerr mounts. Submit a test request and verify it reaches the intended manager. Confirm an unauthenticated visit requires login **before** asking to reopen `requests.krapulax.dev`.
3. Complete **Immich** initial administrator setup privately at `http://photos.krapulax.home`. Under **Administration → External Libraries → Create Library**, select the intended owner, add **import path `/external-library`**, then **Scan New Library Files**. In **Administration → Jobs**, watch Library, Metadata and Thumbnail jobs; compare indexed assets with the NAS source. That read-only path is the existing phone photo/video backup tree (`10.0.40.2:/media/immich/library`); this is **not** a new upload destination and a fresh database will not restore old albums, people or favorites. Do not point the scan at `/data` or move legacy originals. New phone uploads will use Immich's `/data` mount on the same NFS share. Confirm the new admin requires login before asking to reopen `photos.krapulax.dev`; then configure the phone app's server address and test one upload. If phone backups are actually elsewhere on the NAS, identify their exact folder and add a separate reviewed **read-only** mount rather than guessing an import path.

## End-to-end checks and rollback

-   [ ] In SABnzbd and qBittorrent, test the configured paths and client connections without downloading into `/media/tv` or `/media/movies` directly.
-   [ ] Verify an authorized download ends in `/downloads/tv` or `/downloads/movies` (or under `/downloads` if no category folder), is imported into the appropriate `/media` root, and appears in Jellyfin under `/data/tv` or `/data/movies`. For torrents, also confirm continued seeding and whether import copied or hardlinked.
-   [ ] Confirm Prowlarr indexers appear in Sonarr/Radarr, Recyclarr sync has no API failures, and a Jellyseerr request reaches the right manager.
-   [ ] Confirm Immich's external-library scan indexes the existing phone photos, not thumbnails/temporary files, without modifying the original files; test a separate new upload only after admin setup.
-   [ ] Inspect pod readiness, Service endpoints, NFS mounts, application authentication and the public route policy. `photos.krapulax.dev` and `requests.krapulax.dev` intentionally return 404 until setup is secured. Existing public app records resolve to Cloudflare; `cloudflare-dns` remains manually gated to avoid publishing private Envoy IPs.
-   [ ] Choose an **off-host** backup destination for all fresh local-path app databases/config, verify at least one restore, and protect the NFS source independently. NAS snapshots on the same appliance are not an off-host restore.

If an integration fails, disable the relevant download client/indexer/request-app connection in its UI and inspect the app logs and actual container paths; do **not** delete NAS files, retained PVs, old Swarm storage or NFS snapshots. Revert any mistaken GitOps manifest change through a reviewed Git revision. A worker failure may require restoring its node-local PVCs before the app can run elsewhere; the shared media NFS claim alone does not recover databases or settings.
